# Reagent Uses (`reagents`)

Hold a key over a crafting material and its tooltip lists every recipe that uses it. Read only:
it draws tooltip lines and sends nothing anywhere.

It began as the standalone addon Reagent Uses and joined the bundle later, which is why its
standalone keeps the folder `ReagentUses` and the saved table `ReagentUsesDB` (see
`standalone/CLAUDE.md`). `MigrateSaved` in `Core.lua` carries the old standalone's options over.

```
Tailoring 152                               10 recipes
  Bolt of Silk Cloth x4 (used in 52)             Known
  Azure Silk Pants x4                     Trainer 140
Engineering                                  7 recipes
  Solid Dynamite                       Bob, Trainer 175
```

## What the tooltip shows

- Recipes are grouped by profession: the ones this character has first, then ones another tracked
  character has, then the rest.
- A recipe's name takes the crafting window's color for this character's skill: orange, yellow,
  green or grey, and red while the skill is below what the recipe needs to be learned.
- After the name: how many of the material it takes, and how many more recipes use what it makes.
- On the right: who knows it (this character, then up to three other tracked characters), else
  where it is learned and at what skill: Starter, Trainer, Vendor, Drop, Fishing, Quest or Recipe.
- While the key is up, one line says how many recipes use the material (option "Show Hint").

## Where the data comes from

`Features/ReagentUses/Data.lua` is generated by `tools/reagents-data/gen-data.js <build>`:

- **Forever's own client tables** for that build (wago.tools db2 CSVs): which recipes each
  profession window lists, their materials, what they make, their yellow and grey skill, and the
  recipe items that teach them. This includes the recipes Forever added.
- **The cmangos classic-db dump** for what the client does not hold: trainer learn levels, and
  whether a recipe item is sold, dropped, fished or a quest reward. It is vanilla data and only
  fills gaps; Forever's numbers win where both exist.
- A recipe with no teaching item in the client is dropped as unobtainable. The generator prints
  the list.

`tools/test/run.js` fails when `Data.lua`'s build differs from the API allowlist's build, so both
are regenerated together when a game build drops.

## What is saved

In the feature's slice (`ns.db`), next to its options:

- `known["Name-Realm"][line][recipe] = true`: the recipes each character knows.
- `skills["Name-Realm"][line] = rank`: each character's profession skill.

Both are keyed like the character roster (`root.CharKey`, `Core/Characters.lua`). A character's
recipes are read when it opens its own profession window, and when it learns one
(`NEW_RECIPE_LEARNED`). Only tracked characters are recorded or shown, and forgetting a character
drops its records.

## Options

| Option | Default | What it does |
|---|---|---|
| Show With | Ctrl | The key to hold: Ctrl, Alt, Shift, or Always Show. |
| Show Hint | on | While the key is up, one line says how many recipes use the material. |
| Show Other Characters | on | Names your other tracked characters who know each recipe. |
| Hide Grey Recipes | off | Leaves out recipes that can no longer give a skill point. |
| Recipes Shown | 15 (5 to 50) | Past this many, each profession only shows its count. |

`/ru` (or `/reagentuses`) opens the settings, after combat if you are in combat. `/ru chars`
opens the character list.

## Known limits

- Another character is named only after it has opened its own profession window with the feature
  on.
- Material counts come from the client tables. A server hotfix does not show there: the five
  Tailoring bags changed on 2026-11-11 may still list their old bolt counts.
- Trainer levels and drop, vendor and quest sources are vanilla data where Forever's tables are
  silent, so a source Forever changed can be wrong.
